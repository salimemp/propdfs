# ProPDFs brand assets

This directory is the single source of truth for the ProPDFs visual
identity. **Never hand-edit the PNGs in `frontend/web/`** — those are
generated by `scripts/generate_brand_assets.py` from the SVGs in this
directory. To tweak a mark or lockup, edit the SVG and re-run the
generator.

## Files

| File | Purpose | When to use |
| --- | --- | --- |
| `logo-horizontal.svg` | Mark + wordmark side by side | Headers, business cards, email signatures, footers |
| `logo-mark.svg` | Mark only (square) | Where a full lockup doesn't fit; favicon at large sizes |
| `logo-stacked.svg` | Mark on top, wordmark below, tagline underneath | Square placements: avatars, splash screens, OG cards |
| `favicon.svg` | Simplified mark for tiny sizes | Modern browsers' SVG favicon support (Chrome 80+, FF 41+, Safari 16+) |

The PNG mirrors (16, 32, 48, 180, 192, 512 + maskable variants) are
in `frontend/web/` and are generated by the script — they don't live in
git as hand-edited files; the script regenerates them on every brand
update.

## Design language

- **Geometry.** The mark is a 64×64 unit square. The corner radius is
  14 units (≈22% of the side) — large enough to feel friendly, tight
  enough to feel precise. The PDF-fold triangle is 16×16 in the
  top-right (1/4 of the side), positioned so the fold line bisects
  the top-right corner at 45°.

- **The "P".** Drawn as a path, not text. The stem is 10 units wide;
  the bowl is a rounded D-shape from y=16 to y=38. The counter (the
  hole inside the P) is 14×8. The stem extends to y=50 — slightly
  below the bowl's baseline — so the P feels weighted toward the
  bottom, the way professional logotypes do.

- **Color tokens.**
  - `--propdfs-navy:  #0F172A` — slate-900, the primary brand color.
  - `--propdfs-red:   #DC2626` — red-600, the accent. Reserved for the
    PDF-fold triangle and the `.text-accent` style.
  - `--propdfs-white: #FFFFFF` — wordmark on light backgrounds,
    counter on the mark.
  - For dark-background variants the navy becomes `#F8FAFC` (slate-50)
    and the white stays white. Don't add a new token — just invert
    the navy and the white.

## Regenerating the raster assets

```bash
# macOS — install libcairo (one-time)
brew install cairo

# Render every PNG from the SVGs in this directory
DYLD_LIBRARY_PATH="/opt/homebrew/Cellar/cairo/1.18.4/lib" \
  python scripts/generate_brand_assets.py
```

The script writes to `frontend/web/`:

```
favicon-16.png         favicon-32.png         favicon-48.png
apple-touch-icon.png   icon-192.png           icon-512.png
icon-maskable-192.png  icon-maskable-512.png  og-default.png
twitter-card.png
```

Maskable variants have a 40% safe-area inset (per the W3C PWA spec) so
Android / iOS / ChromeOS can crop the icon into any shape — circle,
squircle, teardrop — without losing critical content (the P).

## Don't

- Don't change the navy or red. They're tested for contrast at every
  size and across the WCAG 2.1 AA threshold. A slightly different
  blue or red is the most common mistake that breaks the brand.
- Don't add a gradient to the navy square. The mark is intentionally
  flat — gradients cheapen it at favicon sizes and don't render in
  the Chrome new-tab favicon at all.
- Don't add text inside the favicon (besides the P). "ProPDFs" full
  text at 16×16 is illegible; the wordmark only works in the
  horizontal lockup.
- Don't add drop shadows, bevels, or 3D effects. Modern professional
  brand marks are flat.
